# HTTP 接口

NovelTTS 可以在本机开启一个 HTTP 服务，供阅读器等应用查询音色并合成语音。合成走与应用内朗读相同的链路，角色规则和替换规则同样生效。

HTTP 采用应用「书籍角色」中当前选中的书籍及固定音色绑定，与系统 TTS 共用同一个选择；未选书时使用全局角色。此接口没有自动识别或切换书籍的参数。换书后，新规划使用新选择，已捕获的请求和阅读器缓存音频不重建。

## 启用

在「设置 → 外部调用」里开启。

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 开关 | 关闭 | |
| 绑定地址 | `127.0.0.1` | 只有本机应用能访问 |
| 端口 | `8080` | 可设为 1024–65535 |
| 令牌 | 空 | 为空时不鉴权 |

绑定 `0.0.0.0`（允许局域网访问）时必须设置令牌，否则拒绝启动。服务由前台服务持有，退出界面后继续运行。

> 局域网访问使用明文 HTTP，令牌和文本都不加密，请只在可信网络中使用。该场景尚未经过充分的真机验证。

## 鉴权

设置了令牌后，除 `/health` 外的接口都需要携带令牌。按以下顺序取第一个存在的值：

1. 请求头 `X-Token: <令牌>`
2. 请求头 `Authorization: Bearer <令牌>`
3. 查询参数 `?token=<令牌>`

建议使用请求头，查询参数容易留在日志和历史记录里。

所有接口（包括 `/health`）都会检查来源：携带 `Origin` 的请求返回 403；提供 `Host` 时必须符合主机语法，绑定 `127.0.0.1` 时只接受 `localhost`、`127.0.0.1` 或 IPv6 loopback。为兼容已有原生客户端，暂时允许缺少 `Host`。网页不能直接跨源调用此接口。

## 接口

### `GET /health`

不需要鉴权。

```json
{ "status": "ok", "voices": 63 }
```

`voices` 是当前可用的音色数。结果来自最多 5 秒的可用性快照；应用内安装、删除、许可证和音色覆盖变更立即使快照失效。

### `GET /voices`

返回可用音色列表。注意外层是对象，不是裸数组：

```json
{ "voices": [ ... ] }
```

每个音色的标识是它的系统音色名，形如 `multitts:<packId>:<engineCode>:<voiceCode>`，用于 `/tts` 的 `voice` 参数。

### `GET /tts`、`POST /tts`

合成一段文本。

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `text` | 字符串 | — | 必填，最多 5000 字 |
| `voice` | 字符串 | 应用里设置的旁白音色 | 系统音色名。指定后只替换旁白音色，对话和自定义角色仍按规则分配 |
| `rate` | 数字 | `1` | 语速倍率，0.25–4 |
| `pitch` | 数字 | `1` | 音调倍率，0.25–2 |
| `volume` | 数字 | `1` | 音量倍率，0–1 |
| `format` | 字符串 | `wav` | 只支持 WAV；`mp3` 返回 400 |

`rate`、`pitch`、`volume` 相当于应用里的全局滑块，会再与音色默认值和角色倍率相乘。超出范围的值会被拒绝，不会被静默截断。

GET 使用查询参数；POST 使用 JSON 请求体：

```powershell
$body = [System.Text.Encoding]::UTF8.GetBytes('{"text":"他笑道：“走吧。”","rate":1.2}')
Invoke-WebRequest -Uri 'http://127.0.0.1:8080/tts' -Method Post -ContentType 'application/json' -Headers @{'X-Token'='<令牌>'} -Body $body -OutFile 'out.wav'
```

```powershell
Invoke-WebRequest -Uri 'http://127.0.0.1:8080/tts?text=%E4%BD%A0%E5%A5%BD' -Headers @{'X-Token'='<令牌>'} -OutFile 'out.wav'
```

以上为 PowerShell 示例；`127.0.0.1` 指发出请求的设备，在电脑执行前需要已有端口转发或替换为允许访问的地址，并填入实际令牌。

成功时返回 `audio/wav`：24 kHz、16 位、单声道 PCM，带 44 字节的 RIFF 头。

### `GET /legado`

返回可导入[阅读（Legado）](https://github.com/LegadoTeam/legado)的 HttpTTS 配置数组。配置使用 POST JSON，把阅读的 `speakText` 作为文本、`speakSpeed / 10` 作为语速，令牌放在请求头里。

返回内容里**包含令牌**，请不要公开分享。

> 配置的生成和协议已核对，但尚未在阅读应用里完成实际导入与朗读的验收。

## 错误

错误响应是 JSON：

```json
{ "error": "unknown_voice", "message": "..." }
```

| 状态码 | 含义 |
| --- | --- |
| 400 | 参数非法、JSON 格式或结构不合法、音色不存在或不可用（`unknown_voice`）、不支持的 `format` |
| 401 | 令牌缺失或错误（`unauthorized`） |
| 403 | 请求含 Origin（`browser_origin_denied`），或本机监听收到非本机 Host（`host_denied`）；Host 格式错误返回 400 `invalid_host` |
| 404 | 路径不存在 |
| 405 | 方法不支持；响应带 `Allow` 头 |
| 411 | 请求体缺少长度信息 |
| 413 | 请求体超过 4 MB，或合成结果超过资源上限 |
| 503 | 连接队列已满，或合成后端繁忙 |
| 504 | 请求超过截止时间 |

超时发生在阻塞的读写过程中时，连接可能被直接断开而没有响应体。

语音包里声明但后端不支持的音色（例如百度、讯飞的音色）请求时会返回 400 `unknown_voice`。

没有可朗读片段，或整次合成正常结束但没有音频时，返回 400 `no_audio`。音频收集超过预算或内存分配失败返回 413；错误 JSON 形状保持一致。

## 限额

| 项目 | 上限 |
| --- | --- |
| 单次文本 | 5000 字 |
| 请求体 | 4 MB |
| 请求行 | 8 KB |
| 请求头 | 32 KB，64 条 |
| 单次响应的音频 | 32 MB |
| 并发 | 3 个处理中，9 个排队，超出返回 503 |

请求体支持 `Content-Length` 或单一的 `chunked` 编码，两者同时出现或重复出现会被拒绝。

合成后端另有全进程的并发限制，应用内朗读和系统 TTS 正在大量合成时，HTTP 请求可能收到 503，稍后重试即可。

## 客户端注意事项

- 发送完请求后可以半关闭连接（只关闭写方向），服务端仍会返回音频。
- 断开连接不保证立刻停止合成，但每个请求都受截止时间约束，不会无限占用资源。
- 相同的文本、音色和参数会命中音频缓存。
- 背景音乐只用于应用内播放，不会混入 HTTP 返回的音频。
