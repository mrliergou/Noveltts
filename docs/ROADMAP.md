# 路线图

本文说明 NovelTTS 已经做到什么、正在验证什么、接下来打算做什么，以及明确不做什么。排期没有承诺日期；条目的先后代表优先级。

状态标记：✅ 已实现并在真机验证　🟡 已实现，真机验证不完整　🔲 未开始

## 项目目标

把 NovelTTS 做成一个独立工作的 Android TTS 引擎：导入离线或在线语音包后直接发声，被系统识别为 TTS 引擎，并且在朗读小说时把旁白和不同角色的对话交给不同音色。

## 近期：把已实现的功能验证完整

当前的首要工作不是加功能，而是补齐真机验证。上表中 🟡 的条目都在这个范围内，主要包括：

1. **并发编辑的可靠性**：旧页面上执行删除、移组、排序、还原；导入预览过期后的二次确认；屏幕旋转时保存。
2. **真实音频与并发**：两个后端的长段、最低语速、超限、停止与迟到回调；应用内、系统 TTS、HTTP 同时请求时的繁忙错误、各自取消和内存峰值。
3. **播放体验**：预取后的段间等待、朗读中试听后恢复、尾音排空、长时间锁屏朗读。
4. **音色与语音包管理**：逐音色设置的继承与回滚，包的重导入、更新确认与损坏恢复。
5. **更多环境**：Android 14 及以上版本、其他厂商 ROM、TalkBack 全路径、局域网转发。

## 中期

### 更多合成后端

BDoTTS（百度在线）、讯飞配音、BDeTTS（番茄畅听离线）的语音包已经可以导入，但对应的后端没有实现，这些音色不能发声。

接入每个后端需要补齐协议实现或运行库、合法的授权资源和适配器，并完成注册、参数、合成与取消的验收。只把引擎代码加进支持列表不算完成。

### 缩短首段等待

目前每一段都要整段合成完才开始播放，第一段的等待最明显。分两步：

1. **首段短切分**（已有实验实现，默认关闭）：把第一段在不超过 96 字处切开，先合成较短的前半段。需要在同一设备、同一音色和参数下采集至少 30 组配对测量，首音中位数改善不低于 10% 且尾部延迟不变差，才允许开启。目前还没有配对数据，不宣称有收益。
2. **渐进解码与播放**（🔲）：边接收边解码边播放。需要先解决取消、重试不重复播放和缓存完整性的问题。

### 本地 TTS 桥接

把设备上其他 TTS 引擎的音色作为一类后端接入。适配器代码已存在，但语音包声明到音色注册的链路没有接通，设置入口目前隐藏。接通需要覆盖声明、注册、枚举、三入口合成、拒绝自我委托和取消的完整流程，并且不能把第三方音源描述成本应用的音源。

### 阅读应用联动

[阅读（Legado）](https://github.com/LegadoTeam/legado)的 HttpTTS 配置已经能生成并通过协议核对，但还没有在阅读应用里实际导入并完成朗读验收。

### 语音包管理

- 在线目录的增量刷新（ETag）与下载失败自动重试。
- 语音包发布者签名校验（目前的 SHA-256 只防传输损坏）。

### 工程与适配

- 拆分 `MainViewModel`：按播放、规则、语音包、备份、转发逐步抽出可测试的操作。
- 清理不再被产品调用的早期代理实现。
- 大字号、横屏、小屏与键盘弹出时的布局适配。
- 决定仓库的协作形态：是否公开构建配置与测试，以及如何提供合法的原生依赖。目前仓库只分享源码，见 [README](../README.md#关于本仓库)。

## 远期候选

以下功能有价值，但范围较大或存在兼容风险，需要单独设计后再决定是否做：

| 候选 | 说明 |
| --- | --- |
| 音色 ID 前缀迁移（`multitts:` → `noveltts:`） | 必须一次做完并长期兼容旧 ID；外部阅读器里保存的音色需要用户重选一次 |
| 说话人归属增强 | 嵌套引号、代词指代、无提示的一问一答。先收集真实误判语料与预期结果，再决定怎么做 |
| 自动发现新人物并分配音色 | 与「结果可预期」的原则有冲突，需要先确定交互方式 |
| 快捷设置磁贴 | 快速开关 HTTP 转发 |
| 逐词高亮 | 需要后端提供词边界信息 |
| 音素编辑器 | 目前多音字靠替换规则处理 |
| 通用的自定义 HTTP 引擎 | 让用户自行配置第三方接口 |

## 明确不做

- **兼容 tts-server-android 或原版 MultiTTS 的 JavaScript 插件**：执行不可信脚本带来的安全面与本项目的方向不符。
- **用大模型识别人物**：角色归属保持确定、可离线、可解释。
- **内置或分发任何模型、原生库、许可证**：用户需要自行取得合法授权。
- **把「转发给另一个 TTS 引擎」作为默认实现**：本项目的定位是自己合成。
- **引入数据库**：规则与设置继续使用 JSON 文件和 SharedPreferences。

## 已知问题

- 一问一答都没写说话人时，按「沿用上一个说话人」会读成同一个人。可在设置里改为使用默认对话音色。
- 全局倍率与角色倍率相乘后触及上限时，继续调高没有变化。
- 选中状态的标签底色和滑块未激活轨道仍是 Material 3 的默认淡紫色，与主题不协调。
- 当前段很短或下一段合成比播放慢时，段间仍然会有等待。
