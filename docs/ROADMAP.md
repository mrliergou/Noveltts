# 项目目标与路线图

更新：2026-11-25。本文是总目标、范围与方向决策的唯一入口。近期执行步骤和未关闭问题分别维护在本机 `docs/PLAN.md`、`docs/ISSUES.md`，不随仓库分发。已实现功能由 [README](../README.md) 概览，技术行为由 [架构说明](ARCHITECTURE.md) 维护。

## 总目标

把 NovelTTS 做成可独立工作的 Android 小说朗读引擎：导入用户提供的语音包后，由本应用后端直接合成；应用内、Android 系统 TTS 和 HTTP 入口复用同一套文本规则与合成逻辑，让旁白和已配置角色使用可预期的音色。

当前阶段的产品目标是降低多角色朗读的配置门槛：用户选择一组声音后即可开始听，在阅读中逐渐积累人物，同一个人物的声音稳定，识别错误容易纠正。验证已有链路和收敛维护复杂度围绕这条主线推进。

2026-11-25 用户确认按“按书积累角色 + 固定声音池”的方向记录并开始执行。人工书籍人物、稳定分配与纠错已接入本地实现，正在完成对应验收；自动发现仍未开始。以下保留完整目标与约束，当前行为以 ARCHITECTURE 为准。

同日按用户要求优先优化书籍角色与常用设置：书籍/人物搜索、声音池批量选择、编辑操作区、主题首页直选和顶栏快捷入口已实现，本地构建与 JVM 通过；当前界面版本已安装，主要真机交互与 Android 书籍探针通过，窄屏、大字号及无障碍等适配验收仍未完成。这项调整不扩大人物发现或后端范围。

## 当前范围

| 范围 | 保留的能力与边界 |
| --- | --- |
| 合成与接入 | Edge Read Aloud 在线、微软 Embedded Speech 离线；应用内、系统 TTS、HTTP 共用规划与合成 |
| 多角色 | 保留用户配置和归属规则；新增方向为按书保存人物、声音池固定绑定、保守增量发现和人工纠错，不承诺发现所有人物 |
| 语音包 | YAML/旧包兼容、导入与更新、音色可用性、逐音色设置；导入声明与能够合成严格区分 |
| 播放 | 试听、暂停续读、逐段跳转、预取、前台会话与故障恢复 |
| 数据 | 角色/替换规则、阅读方案、缓存、诊断、显式备份与事务恢复 |
| 工程 | 保留现有行为的小步改进、对应版本的证据、清楚的模块职责和交接文档 |

当前可合成的后端只有 `edgetts` 和 `microsoft`。百度、讯飞等包能被解析不等于具备相应后端；本地桥接也未完成正常注册链路。具体格式看 [语音包格式](VOICE_PACK_FORMAT.md)，不要在多个文档另建支持矩阵。

## 已确认方向：按书积累角色与声音池

默认体验采用“选择当前书籍方案 → 选择声音池 → 开始朗读 → 逐渐积累人物”。整本小说导入仅作为后续可选的提前填充入口，与渐进发现共用候选、人物、别名和音色绑定，不能另建一套角色系统。第一人称、别名及称呼会影响频次，出现次数只用于常见人物排序，不自动认定主角，不随排名变化重新配音。

人物发现、对白归属和声音分配是三个独立环节。现有归属规则可复用；候选不能因为“已分配声音”就被当成识别正确。首版不引入大模型或新依赖，不按姓名推断性别或年龄。

| 边界 | 已确认的产品约束 |
| --- | --- |
| 按书隔离 | 用户手动选择当前书籍方案；无书籍身份时不自动写入人物。先验证实际阅读器的入口、版本和切分，不推测换书或把调用方 UID 当书籍 ID |
| 固定绑定 | 第一次分配后保存稳定人物 ID 与完整音色 ID；重启、回读、角色排序、频次和声音池顺序变化都不重配已有角色 |
| 声音池 | 用户选择音色，首次分配只使用当前可用项；优先未占用项，耗尽后稳定复用，空池使用默认对话音色并提示。新增可用音色只影响尚未绑定的人物 |
| 故障回落 | 指定音色不可用时只临时回落默认，不改持久绑定；恢复后使用原声。运行中故障与注册表不可用分开处理，遵守取消、截止时间和终止错误约束；默认也不可用则明确报错 |
| 保守发现 | 明确说话句式产生候选，可靠证据才允许自动启用；不确定对白先用默认对话音色，不要求用户在播放中逐条确认 |
| 人工纠错 | 支持改名、合并别名、改声、忽略错误候选；人工确定的身份和音色优先，合并时明确保留哪个人物及其绑定，不能覆盖已有规则和定向替换 |
| 会话边界 | 人物表长期保存，对话上下文短期有界；换书、跳转、取消、重试、并发和迟到结果不得污染其他书或重复创建人物。不能可靠判断连续性时清空短期上下文 |
| 无额外等待 | 角色处理不能为等待下一次请求而阻塞当前合成；请求正文不默认落日志。整本扫描另有大小、进度、取消和去重边界 |

落地顺序为输入边界与基线 → 人工人物表、固定声音池及纠错 → 保守增量发现 → 可选整本扫描。前两步先构成可验证的小闭环；设备与可靠性缺口持续保留，不要求先完成所有结构整理才验证产品价值。

## 当前阶段的完成标准

1. 三入口在相同输入、最终参数与缓存条件下行为一致；失败、停止、超时和零音频都有明确结果。
2. 规则、语音包与恢复操作保留用户数据，过期界面不能覆盖新配置，失败能恢复或给出可操作反馈。
3. 文档区分已实现、JVM 通过、设备通过和未覆盖；真实设备与产物哈希对应，保留验证范围。
4. 按书隔离、固定音色、池耗尽、音色失效恢复和人工纠错有回归；增量发现用真实样本分别衡量误识别、遗漏和额外等待，不以候选数量证明效果。
5. 长段、并发和交互缺口逐项关闭；结构改进由具体问题驱动，不一次重写整个应用。

以上是方向标准，不表示当前已经全部满足。具体缺口只维护在 ISSUES，近期顺序只维护在 PLAN。

## 暂缓与待决策方向

这些是候选池，不是执行队列。没有排入 PLAN 就不会因旧研究文档的优先级而自动开工。

| 编号 | 方向 | 进入执行前需要明确 |
| --- | --- | --- |
| D-01 | 新后端、通用 HTTP 引擎、开源离线引擎 | 用户需求与收益、可使用的接口/资源、凭据配置、音频格式、取消与缓存身份；旧原版分支映射只是研究线索 |
| D-02 | 本机其他 TTS 的桥接 | 是否暴露给系统、怎样防自我委托、声明到注册的完整链路、连接级 stop 的隔离；隐藏入口保持现状 |
| D-03 | 扩展阅读器联动 | 系统 TTS 的阅读输入边界核对已进入当前主线；其他阅读器、定制书籍/章节协议、HTTP 自动切书仍暂缓，不能把配置导出成功当联动成功 |
| D-04 | 首段实验与渐进播放 | 同设备/音色/参数配对证据，以及取消、续读、重试和缓存的一致性；实验门槛见 ARCHITECTURE |
| D-05 | `multitts:` 音色 ID 迁移 | 完整旧引用兼容与用户迁移方案，涵盖角色、方案、快照、备份和外部客户端；不能只批量改字符串 |
| D-06 | 可复现构建、正式签名/发布、机外备份 | 版本发布按用户明确请求执行；可复现构建、正式签名迁移、依赖许可与机外备份方案仍需单独确定，不因发布自动扩大源码分享范围 |
| D-07 | 进一步 UI/阅读能力 | Quick Settings、逐词高亮、音素编辑和额外动效等需要明确用例与数据来源；顶栏主题快捷入口已按用户要求纳入当前交互优化，复用三档主题，其他未实现入口不占位 |
| D-08 | 语音包目录与来源验证 | ETag 增量刷新、下载失败重试、发布者签名；先明确使用需求与失败/更新语义，当前 SHA-256 不等于发布者认证 |
| D-09 | 复杂角色归属增强 | 按书角色与保守增量发现已纳入主线；嵌套引号、代词、无提示问答、逐片段改派及旧模式默认策略变化，仍需独立样本和决策 |
| D-10 | 整本小说提前扫描 | 共用主线人物表与候选流程；先完成渐进方案，再明确导入格式、大小预算、取消恢复和别名纠错。频次只排序，不自动认定主角 |

两份旧 CCG 研究中的“能力表 → 桥接 → HTTP → 更多引擎”顺序没有成为产品承诺。当前已确认的可用性提示问题在 I-007，修正它不需要先建设整套新后端架构。

## 当前不做与保留约束

- 不执行原版 MultiTTS / tts-server-android 的 JavaScript 插件，不承诺兼容其完整配置生态。
- 首版人物发现与分配不使用大模型；未确认候选不强行归属，现有手动角色规则保持兼容，多音字仍通过替换规则处理。
- 不把系统代理作为默认合成实现，不把第三方音源描述成本应用自有音源。
- 默认保留 JSON / SharedPreferences、用户原数据、现有依赖与稳定音色 ID；不为整理架构自动换数据库或 SDK。
- 不在源码仓库分发模型、原生库、许可证或用户数据；当前公开仓库仍不能直接克隆构建。
- Edge 使用非官方接口；它的上游稳定性不由本项目保证，不能把接口可用当永久前提。

实施约束与文档更新规则见根目录 [AGENTS](../AGENTS.md)。新的用户任务可以调整范围；调整时在此替换对应决策，并同步 PLAN/ISSUES，不另建一份长期路线图。
